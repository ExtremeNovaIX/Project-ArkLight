# ArkLight 视觉语言

## 名称

**ArkLight Archival Instrumentalism**

中文可称为“档案仪器主义”或“洁净工程复古未来主义”。

这套视觉语言描述一位现代工程师为了追求复古美感而设计的界面。它不是旧设备的复制，也不是做旧效果。界面应该干净、准确、克制，第一眼接近空白，继续观察时才逐渐发现纹理、图形和微信息。

## 核心原则

1. **旧而不脏**：使用米白材料、印刷感线条和低对比纹理，不使用污渍、锈迹、破损和明显纸张氧化。
2. **空白中存在信息**：主要内容保持清晰，隐藏信息只占据边角和留白。
3. **装饰看起来像功能**：编号、微字、裁切标记和轨道图形应遵循稳定网格，即使内容没有具体意义。
4. **聊天优先**：产品仍是轻量聊天应用，不能变成任务数据库、调查面板或游戏 HUD。
5. **动效响应事件**：动效只发生在打开、切换、聚焦和状态改变时，不持续表演。
6. **少量强识别点**：Orbital Relay、橙色登记刻度、集合几何图标和深空角色舞台构成品牌识别。

## 配色

| 角色 | 色值 | 使用方式 |
|---|---:|---|
| Paper | #F2EBDD | 主背景 |
| Shell | #F4EEE2 | 弹窗和大面积工作区 |
| Input Paper | #F8F3E9 | 输入框、选择器 |
| Paper Light | #FFFDF8 | 高光文字、图标轨道 |
| Ink | #202322 | 主文字和结构线 |
| Black | #090B0C | 深空、强对比控制面 |
| Orange | #F26422 | 登记刻度、焦点、关键状态 |
| Teal | #2A7C79 | 在线、已保存、可用状态 |

规则：

- 橙色面积应小于页面面积的 3%。
- 青绿色只用于状态，不作为大面积背景。
- 结构线通常使用 Ink 的 8% 至 18% 透明度。
- 背景隐藏图形使用 Ink 的 2% 至 5% 透明度。
- 暂不使用红黄蓝分段线系统。

## 字体角色

- **Display**：Bahnschrift SemiCondensed，用于短英文标题、编号和品牌名称。未来可替换为经过授权的 Avant Garde 类字体。
- **Sans**：Microsoft YaHei UI，用于中文界面、说明和表单。
- **Mono**：Cascadia Mono，用于微信息、序列号、版本和伪技术标注。

限制：

- Display 不用于长段落。
- 单个页面最多同时出现三种字体角色。
- 中文正文保持 12 至 15 px 等效字号。
- 微信息允许 8 至 10 px，但不能承载用户必须理解的内容。

## 布局与留白

- 使用稳定的左侧索引与右侧工作区结构。
- 设置页基准尺寸为 1180 × 720。
- 一级导航宽度约为 220–250 px。
- 内容区以单列台账为主，避免卡片网格。
- 分区优先使用间距、字体和细分隔线，不优先使用背景块和阴影。
- 独立对象，例如角色卡片、文件条目和错误消息，可以使用轻边界容器。

## Orbital Relay

构成：

1. 近黑底板。
2. 奶白双轨道圆环。
3. 中央水平通信槽。
4. 单个中继节点。
5. 右下方橙色登记刻度。

尺寸策略：

- 16–32 px：保留底板、双环、通信槽和橙色刻度。
- 48–64 px：允许显示中继节点。
- 128 px 以上：允许增加细微轨道断口。
- 图标内部不使用文字和微信息。

## 集合几何图标

所有分类图标使用同一构造语法：

- 圆环和不完整圆弧。
- 节点和短切线。
- 中央槽、链路或声波阵列。
- 统一线宽与 52 × 52 基准网格。
- 活跃状态使用一个橙色节点，不填充整个图标。

分类：

- 常规：轨道、中心节点和水平轴。
- 模型与服务：重叠环与连接线。
- 游戏联动：交错链路。
- 语音与音频：圆环内的纵向波形阵列。

## 动效

时长令牌：

- Fast：140 ms
- Base：210 ms
- Slow：520 ms

分类切换：

1. 未选中图形保持轻微松散状态。
2. 选中后，各段在 2 至 6 px 范围内归位。
3. 图形整体向上移动约 1 至 2 px。
4. 橙色节点在装配完成时出现。
5. 动画结束后完全静止。

禁止：

- 持续旋转。
- 呼吸光。
- 故障闪烁。
- 弹性缩放。
- 大范围视差。
- 超过 600 ms 的常规交互动画。

系统启用 reduced motion 时应直接显示最终状态。

## 背景与纹理

可使用：

- 原聊天背景的低对比斜向线纹。
- 稀疏点阵。
- 像素化巨构碎片。
- 轨道圆和裁切标记。
- 意义不明确的伪技术微字。
- 部分被裁切的序列号、坐标和数学符号。

隐藏元素必须远离主要标签、输入框和值。用户不需要理解它们，它们只负责建立第二阅读层。

禁止：

- 大面积噪点。
- 明显污渍。
- CRT 扫描线。
- 故障条。
- 霓虹光晕。
- 玻璃拟态。
- 高对比蓝紫渐变。
- 重度纸张氧化黄。

## 设置页

一级分类使用用户语言：

1. 常规
2. 模型与服务
3. 游戏联动
4. 语音与音频

开发术语应退到内容内部或高级区域，例如 runtime、ASR、配置文件名和调试记录。

组件规则：

- 输入框保持传统桌面表单形态。
- 普通设置以“标签 + 说明 + 控件”的台账行呈现。
- 开关使用米白与青绿色工业塑料感，不使用整块黑色卡片。
- 自动保存，不设置显眼的大型保存按钮。
- 关闭按钮保持文字化和低强调。
- 错误和危险操作才使用橙红色边界。

## 检查清单

- 第一眼是否仍然干净和可读？
- 隐藏图形是否需要细看才能发现？
- 页面是否仍然像聊天应用，而不是游戏 HUD？
- 是否存在没有必要的卡片、阴影或圆角？
- 橙色是否只用于焦点和识别？
- 集合图标在停止动画后是否完全静止？
- 中文标签是否避免开发术语？
- 125%、150% 缩放下是否无裁切和横向滚动？
- 键盘焦点与禁用状态是否可辨认？
- 桌面图标在 16、32、64 和 256 px 下是否可识别？
